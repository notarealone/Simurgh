# Query Rewriting for Retrieval-Augmented Large Language Models

- **Authors:** Xinbei Ma, Yeyun Gong, Pengcheng He, Hai Zhao, Nan Duan
- **Year:** 2023
- **Venue:** EMNLP 2023
- **Link:** https://arxiv.org/abs/2305.14283

---

## Summary

This paper proposes the Rewrite-Retrieve-Read (R3) framework, which inserts a dedicated query rewriting step between the user question and the retriever in a RAG pipeline. Rather than modifying the retriever or reader, an LLM first rewrites the query into a retrieval-friendly form before web search is performed. The key advance is a trainable small rewriter that is optimized via reinforcement learning using the downstream reader's performance as reward, allowing end-to-end alignment without requiring gold rewrite annotations.

## Key Contributions

- Rewrite-Retrieve-Read framework: decouples query adaptation from retrieval and generation, making the rewriter independently trainable.
- Demonstrates that prompting a frozen LLM to rewrite queries already improves retrieval quality on open-domain and multiple-choice QA tasks.
- Introduces a trainable rewriter (small LM) fine-tuned with RL feedback from the frozen reader, achieving further gains without gold rewrite labels.
- Shows consistent improvements across diverse QA benchmarks, validating query rewriting as a general-purpose RAG enhancement.
- Establishes that the rewriter can be a much smaller model than the reader, making the approach compute-efficient.

## Relevance to This Thesis

The R3 framework is the direct architectural precedent for Simurgh's Query Rewriter component: Simurgh extends it by conditioning rewrites on a learner profile (grade level, learning style, goal) and replacing the generic RL objective with persona-alignment reward via DPO and LLM-as-judge preference pairs. The finding that a small trainable rewriter outperforms a prompted large LLM supports using a ≤7B PEFT/LoRA model as the rewriter under Simurgh's compute constraints. The RL-from-reader-feedback mechanism maps directly onto Simurgh's offline RL (DPO) loop, where preference pairs are generated by an LLM judge scoring persona fit.

## Notes

- The paper uses web search as the retriever; Simurgh uses a fixed Persian document index, so retrieval feedback dynamics may differ.
- RL training here is online (reward from reader at inference); Simurgh uses offline DPO, which avoids the need for live reader rollouts — more practical under limited GPU budget.
- Reward hacking risk noted by the authors (rewriter gaming the reader metric) is directly relevant: Simurgh must guard against rewrites that score well on the judge prompt but don't genuinely help the learner (see [[methodology]] and [[docs/things-to-consider.md]]).
- Open question: how much does the rewriter need to be aware of Persian-specific retrieval signals (ZWNJ normalization, ye/ke variants) vs. relying on the retriever's tokenizer to handle them?
