# DeepRetrieval: Hacking Real Search Engines and Retrievers with Large Language Models via Reinforcement Learning

- **Authors:** Pengcheng Jiang, Jiacheng Lin, Lang Cao, Runchu Tian, SeongKu Kang, Zifeng Wang, Jimeng Sun, Jiawei Han
- **Year:** 2025
- **Venue:** COLM 2025 (arXiv:2503.00223)
- **Link:** https://arxiv.org/abs/2503.00223

---

## Summary

DeepRetrieval trains a small LLM to **generate retrieval queries with reinforcement learning, using the retrieval outcome itself as the reward** — no supervised query-rewrite labels and no distillation from a larger model. The policy first produces reasoning in a `<think>` block and then the final query in an `<answer>` block; the query is run against a real search engine or retriever, and a retrieval metric (e.g. Recall@3K, NDCG@10, or SQL execution accuracy) plus a format term is fed back as reward, optimized with PPO (KL-regularized to a frozen reference). A 3B model trained this way beats prior supervised state-of-the-art and outperforms GPT-4o and Claude-3.5-Sonnet on 11 of 13 retrieval datasets spanning literature search, evidence-seeking QA, classic IR, and SQL search.

## Key Contributions

- **Reference-free RL for query generation**: optimizes queries directly against retrieval metrics (recall) instead of imitating gold rewrites — removes the need for labeled query-augmentation pairs.
- **Think-then-answer query format**: explicit reasoning trace before emitting the query, improving query quality and interpretability.
- **Small-model efficiency**: a 3B policy surpasses much larger proprietary LLMs (GPT-4o, Claude-3.5-Sonnet) on most benchmarks, and beats prior SOTA (e.g. ~65% vs ~25% recall on publication search).
- **Breadth**: validated across 13 datasets and multiple retrieval back-ends (real search engines, dense retrievers, SQL), showing the recipe is retriever-agnostic.
- Open-source implementation and data.

## Relevance to This Thesis

DeepRetrieval is the modern, compute-friendly upgrade of Simurgh's rewriter precedent ([[query-rewriting-for-retrieval-augmented-large-language-models]]): same Rewrite-then-Retrieve placement, but trained with RL-from-retrieval-outcome on a small model — exactly the ≤7B / PEFT budget Simurgh targets. Two ideas transfer directly. First, the **retrieval-outcome reward** offers an *objective, non-judge* training signal for the rewriter (Recall@K / MRR per persona), which Simurgh can use alongside or as a sanity check against the LLM-judge reward to detect reward hacking. Second, the **think-then-answer format** is a clean way for a persona-conditioned rewriter to reason about a learner's profile before producing the rewritten query. It also reframes a key design decision: Simurgh defaults to offline DPO, but DeepRetrieval shows online RL-with-verifiable-rewards is tractable on a 3B model — a credible alternative worth noting in [[things-to-consider]] ("Which RL algorithm for retriever?").

## Notes

- "Verifiable" reward = retrieval recall against known relevant docs. Simurgh's primary objective is *pedagogical fit*, which is **not** verifiable from retrieval alone — so DeepRetrieval's reward can only train the *retrieval-utility* half of the rewriter, not persona alignment. Likely use: a two-term reward (retrieval recall + judge persona score) or recall as a guardrail metric.
- PPO online training needs live retrieval rollouts each step; cheap with a local BM25/dense index but adds engineering over the offline DPO loop. Budget this if adopting.
- Persian angle: queries are generated by the policy LLM, so the rewriter must emit Persian queries with correct ZWNJ / ye-ke forms to match the index — a Persian-capable small policy model (e.g. Dorna / PersianMind) matters here.
- Same first author as [[s3-you-dont-need-that-much-data-to-train-a-search-agent-via-rl]]; the two together map the "RL trains the search side, generator stays frozen" design space.
